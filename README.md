# Личное расписание Валентины

Расписание занятий по русскому языку и литературе. Нажмите на дату или свободное место дня, чтобы добавить занятие на выбранный день. Поддерживаются удаление, проверка пересечений, экспорт и импорт JSON, переходы по неделям. Время московское (UTC+3).

## Подключение Supabase — обязательно перед использованием

Без настроенного Supabase форма входа отключена, расписание закрыто. Готовность настоящего входа и правил доступа нужно проверить после подключения проекта; локальные проверки с имитацией API этого не заменяют.

1. Создайте проект на https://supabase.com/dashboard. Пароль базы храните у себя; он не используется сайтом.
2. В SQL Editor выполните содержимое `supabase/schema.sql`. Таблица использует Row Level Security: пользователь читает и изменяет только расписание своего аккаунта. Анонимному пользователю доступ не предоставляется.
3. В Authentication → Sign In / Providers включите вход Email/Password, включите публичную регистрацию (Allow new users to sign up). При включённом Confirm email пользователь подтверждает почту по ссылке в письме и затем входит на сайте. В URL Configuration добавьте адрес сайта в Redirect URLs. Для реальных пользователей настройте отправку писем через свой SMTP: встроенная почта Supabase ограничена и может не отправлять письма на произвольные адреса. Социальный вход и вход по ссылке сайту не требуются.
4. Пользователи могут создать аккаунт на сайте через «Регистрация». При необходимости в Authentication → Users → Add user создайте пользователя с почтой и паролем. Если доступна настройка Auto Confirm User, включите её для создаваемого вами аккаунта. Пароль задавайте только в Supabase, не в GitHub и не в чате. Разные аккаунты получают отдельные личные расписания; совместного доступа между аккаунтами пока нет.
5. Из настроек проекта возьмите Project URL и публичный Publishable key (`sb_publishable_…`). Запишите их в `config.js`. Этот файл публичный. Никогда не вставляйте туда secret key, service_role, пароль или строку подключения к базе. Старый публичный anon key тоже поддерживается, но для нового проекта используйте Publishable key.
6. В Authentication → URL Configuration укажите Site URL `https://gnikulshin1201-dot.github.io/-/`.
7. Отправьте config.js в main. В GitHub Settings → Pages выберите Source → GitHub Actions. При необходимости запустите Actions → Publish website → Run workflow.

## Проверка настоящего проекта

- До входа расписание не отображается; неправильный пароль отклоняется.
- Войдите созданным пользователем, добавьте урок по нажатию на дату, перезагрузите страницу: урок должен остаться.
- На втором устройстве войдите в тот же аккаунт, нажмите «Обновить»: должен появиться тот же урок.
- Создайте второй тестовый аккаунт: он не должен видеть данные первого. В SQL Editor/RLS-инструментах дополнительно проверьте, что anonymous не читает таблицу, а authenticated не читает и не обновляет строку другого user_id. Клиентские проверки не заменяют проверку политик базы.
- Проверьте регистрацию с подтверждением почты и без него, а также несовпадение паролей и запрет регистрации в настройках проекта.
- Нажмите «Выйти» и обновите страницу: снова должна появиться форма входа.

Данные занятий хранятся в Supabase. Токены текущего сеанса сохраняются в sessionStorage этой вкладки; пароль не сохраняется. При выходе очищаются сеанс и отображаемые занятия. Для загрузки изменений с другого устройства есть «Обновить». При конфликте версий сохранение отклоняется, чтобы не затереть чужие изменения.

Данные старой версии в localStorage не удаляются и автоматически на сервер не переносятся. Если вы уже пользовались старой версией, сохраните JSON-копию и загрузите её после входа. Импорт заменяет всё расписание аккаунта после подтверждения.

## Локальный запуск

```sh
python3 -m http.server 8000
```

Откройте страницу через HTTP. Сборка и зависимости не требуются. Для разработки нужен отдельный тестовый проект Supabase с такими же политиками. Никогда не используйте привилегированный ключ во фронтенде.

## Выполненная проверка реализации

Через Playwright с имитацией REST API проверены: закрытый доступ без конфигурации, отказ при неверном пароле, вход, добавление по дате, сохранение и загрузка после перезагрузки, конфликт версий, обновление, выход; ширины экрана 1440, 390 и 320 пикселей. Действующий Supabase и SQL-политики пока не проверены: проект ещё не подключён.
